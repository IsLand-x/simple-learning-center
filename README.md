# 学习中心

一个本地优先的个人 EPUB 阅读、RSS 订阅、YouTube 视频学习与 AI 学习应用。项目由 React Web 客户端和单用户 Node 数据服务组成，书籍、订阅、视频字幕、笔记、进度与对话统一保存在独立数据目录中，因此更换浏览器后仍可继续使用同一份资料。

## 功能概览

### 本地书架

- 批量导入 EPUB，以卡片形式展示书籍。
- 封面直接从 EPUB 文件读取；已有书籍缺少封面元数据时会从服务端保存的原文件自动恢复。
- 支持按书名或作者搜索，并按全部、阅读中、已读完筛选。
- 展示封面、作者、当前章节、阅读进度与最近阅读时间。
- 删除书籍时同步清理 EPUB、笔记、高亮、评论、对话、阅读记录和书内索引。

### RSS 订阅与时间线

- 支持订阅 RSS、Atom 与 RDF 订阅源，并按文章、视频和社交媒体三种类型标记。
- 左侧订阅源顶部提供“日报”“未读”“收藏”“全部”聚合；日报按日期列出 AI 整理结果，今天的条目显示“正在产出中”。订阅源同时支持文件夹分类、重命名，以及基于 React Beautiful DnD 交互的文件夹排序、订阅源排序与跨文件夹移动，并支持鼠标、触屏、键盘拖动和 OPML 导入导出。
- 内容列表支持今天、最近 7 天和全部三个时间范围，可搜索标题、作者、订阅源与正文，并在列表、时间线和详情正文中以黄色同步高亮命中的关键词；同时支持逐条切换已读状态、按订阅源或当前列表一键已读，并区分已读与未读标题。
- 当前列表来源、时间范围、实际订阅源 ID 和文章 ID 会同步写入 RSS 页面 URL，刷新或复制链接重新打开后可恢复到同一篇内容；失效的订阅源或文章参数会自动回退。
- 桌面详情区将标题与正文限制在稳定行宽并居中展示；长文章会从正文一级至三级标题生成左侧目录，滚动时同步当前章节。正文按原文结构展示行内配图和可点击链接；链接在新窗口打开，图片支持点击查看并在 50%–400% 之间缩放；长链接、代码和表格会在正文宽度内折行，避免横向滚动。
- 选中 RSS 正文后可直接提问、高亮或添加评论；标注与文章一同保存在服务端，带评论的划线会集中展示在右侧评论面板并可跳回原文，选中文字提问时会作为独立引用加入 AI 输入框。
- RSS 阅读区复用读书模块的阅读样式预设，可调整纸张背景、字体、字号、纹理和段落松紧；进入详情后会使用已配置的内部 AI 自动生成简短但完整的摘要，也可继续在 AI 侧边栏中追问。详情右上角支持读取网页原文、翻译当前页面，以及在原文和中文译文之间切换；读取原文优先解析网页首包与结构化文章数据，遇到依赖 JavaScript 的动态页面时会在已配置 Jina Reader 的前提下回退到浏览器渲染读取。
- 日报会读取当天未读内容，合并上一版结果，按事件和主题去重后生成带订阅源名称与原文链接的 Markdown 报告。齿轮入口可设置 Prompt、模型，以及每 2 小时、每 4 小时或每天指定时刻自动执行；定时任务由 Node 服务端运行，浏览器关闭后仍会继续，但应用服务或容器重启会中断正在生成的内存任务。
- 时间线侧边栏按日期汇总当前范围内的更新，AI 与时间线均可通过右侧功能栏随时展开、收起和拖拽调整宽度。
- 手机和 Android PWA 在 `800px` 及以下切换为订阅源、内容列表、文章详情三个单栏阶段：前两级保留全局底部导航，文章详情底部仅提供上一篇、下一篇和更多；更多浮层内的 AI、样式和时间线复用读书模块的底部抽屉交互，并处理系统安全区与最小 44px 触控目标，收藏仍保留在详情顶栏。
- RSS 的订阅源树、内容列表、正文渲染、标注、AI 与时间线仍由桌面端和移动端共享；仅将移动端顶栏、阶段导航、底部工具栏和抽屉容器拆为 `RssMobileWorkspace`，避免为 Android 维护第二套业务状态或数据逻辑。
- 订阅源、文件夹、历史内容、已读、收藏和标注统一写入服务端数据目录；每次刷新按条目 ID 合并，不因下一次拉取而裁掉旧内容。管理入口使用长抽屉集中编辑文件夹、内容类型、归属关系和“自动原文”开关，该开关也会随 OPML 导入导出。
- 订阅抓取由 Node 服务端完成，仅接受 HTTP/HTTPS 地址，并拒绝本机、局域网和其他私有网络目标。服务端默认每 30 分钟刷新一轮，先随机打散订阅源，再根据数量错峰串行拉取，浏览器关闭后仍会继续。详情工具栏可手动重新读取当前网页正文；开启“自动原文”后，每轮刷新最多依次补抓 6 篇尚无完整正文的内容，避免同时请求过多站点。
- 当天没有内容时自动回退到最近 7 天，仍无内容时明确显示空状态；订阅源推荐在对话中按需提供，不占用管理界面。

### YouTube 视频学习

- 视频资料栏按频道分组，只展示视频名称与时长；标题栏右侧的加号会打开添加弹窗，可粘贴标准、短链接、Shorts、Live 或 Embed 形式的 YouTube 地址。
- Node 服务通过 `youtubei.js` 读取公开视频的标题、频道、时长和字幕。视频始终使用 YouTube 官方 iframe 播放，不下载或保存视频文件；服务端只持久化元数据、字幕、播放进度、笔记与 AI 对话。
- 对话稿支持英文原文、简体中文和双语三种模式。中文字幕优先使用 YouTube 字幕轨道提供的翻译；点击任意字幕可以跳转到对应播放时间，并自动跟随当前播放位置。
- 中间播放器下方提供时间点笔记输入框，保存时自动绑定当前播放时间和对应的中英文字幕；右侧笔记面板以评论卡片集中展示时间点笔记，并提供 Tiptap Markdown 学习笔记。
- 右侧字幕、AI 和笔记共用可调整宽度的辅助面板。视频 AI 助手会通过服务端工具读取实际字幕和视频笔记，不会假装看到了视频画面。
- `800px` 及以下使用单栏视频详情：播放器和快速笔记位于上方，字幕、AI、笔记位于下方并由专用底栏切换；进入视频详情后隐藏全局底栏，为学习区域保留空间。

### Folo 与 RSSHub 接入策略

- 学习中心保持为标准 RSS / Atom 阅读器，不依赖 Folo 的账号、数据服务或私有 API；和 Folo 等阅读器交换订阅时优先使用 OPML。Folo 提供 feeds、subscriptions 和 RSSHub 等 API 路由，但直接绑定这些接口会把本地数据模型耦合到外部服务。
- 有原生 RSS 时直接订阅原生地址；没有原生 RSS 的社交媒体、视频平台或动态网页，交给 [RSSHub](https://github.com/DIYgod/RSSHub) 生成标准订阅源，再由学习中心拉取。RSSHub 已维护大量平台路由，并与 Folo 配套使用，适合作为独立适配层。
- 不在学习中心服务端内置微博、X、微信公众号等平台爬虫。登录态、反爬规则和页面结构变化会显著增加维护与安全成本；推荐部署自己的 RSSHub 实例，并把实例生成的 URL 当作普通订阅地址添加。公共 RSSHub 实例只适合试用，私有或带 Cookie 的内容不应交给不受信任的实例。
- 后续如果要提升体验，可以增加“RSSHub 实例地址 + 路由生成器”，但抓取、缓存和失败隔离仍由 RSSHub 负责，学习中心只消费标准输出。

### EPUB 阅读器

- 使用 Foliate.js 提供分页、目录导航、CFI 定位、触控手势和标注层。
- 支持工具栏、方向键、触摸左右滑动和触控板双指横向滑动翻页；跨章节时会双向预载相邻章节并沿用当前阅读字体，避免章节首尾出现空白或字体闪烁。
- 自动保存章节、整体进度和精确 CFI，刷新或重新进入时恢复最后阅读页面。
- 目录、阅读区和右侧辅助面板支持展开、收起与拖拽调整宽度。
- 提供多套阅读主题，并支持自定义字体、纸张颜色、文字颜色、纹理、字号和内容密度。
- 可选中文字体包括系统宋体、思源宋体、霞鹜文楷、霞鹜 Bright、思源黑体和苹方。

### 高亮、评论与笔记

- 选中正文后可直接提问、高亮或添加评论。
- 高亮基于 EPUB CFI 保存，调整面板宽度后仍能对应原文。
- 点击高亮可取消、在高亮面板中查看，或继续添加和编辑评论。
- 笔记支持 Markdown 编辑，正文以独立 `.md` 文件保存在数据目录。
- 选中文字提问时，原文以独立引用标签加入 AI 输入框，不与用户问题混合。

### AI 阅读助手

- 支持管理多个 OpenAI 兼容供应商和模型。
- 模型请求由 Node 服务端发出，不受浏览器 CORS 限制，可用于 Kimi for Coding 等不开放浏览器跨域访问的兼容端点。
- 使用 Vercel AI SDK 处理流式对话、多步工具调用和 OpenAI 消息格式；生成片段通过服务端事件流实时推送到页面，并在工具调用接近上限时自动收束为完整回答。
- 对话以服务端异步任务运行；关闭或刷新网页不会取消生成，重新打开同一对话后会自动继续显示进度和结果。
- 使用 Semi Design AI Chat 展示用户消息、助手消息、模型思考和工具调用过程。
- Agent 可以按需读取当前书籍、章节、笔记、高亮、评论和阅读轨迹。
- 支持搜索整本 EPUB，并继续读取命中段落的相邻上下文。
- 可单独配置 Jina Search 和 Jina Reader，用于联网搜索与网页读取。
- 支持新建对话、继续历史对话、快速跳转用户消息和右键删除对话。

> 思考过程和工具调用能否完整展示，取决于模型及兼容端点是否返回相应字段。

### 阅读轨迹与 PWA

- 自动记录阅读开始时间、结束时间和持续时长。
- 同一天的阅读记录合并展示，并提供最近 12 周热力图。
- 支持浅色和深色主题、响应式布局与 PWA 安装；桌面安装窗口默认使用保留系统顶部标题栏的 `standalone` 模式。
- 手机和平板竖屏使用独立响应式视图：书架和设置采用底部导航，书架以双列封面展示；阅读页底部直接提供目录、上一页、下一页和更多功能入口，单击正文非链接、非选区区域可同时隐藏或恢复顶部栏与底部栏，支持沉浸阅读；栏位显隐时会保留固定的正文分页区域，避免文字重排和页码跳动，隐藏态顶部保留书名与当前章节；支持左右滑动翻页和原生文字选区，触摸位移按屏幕动画帧合并、阅读进度在空闲时批量保存，以减少连续翻页卡顿；长按选字与拖动选区（包括章节第二页及后续页面）时会直接锁定 Foliate 分页手势，不会误触上一页或下一页；活动端点在页首或页尾停留 2 秒时，可在同一章节内自动翻到上一页或下一页，并从新页末字或首字继续拖选，章节边界不会自动跨越；目录从侧边以直角面板滑入，打开时会将当前章节定位到可视区域中央；更多功能中的 AI、笔记、高亮、评论和阅读样式共用约九成屏高的动画底部抽屉，不压缩正文宽度；浮层打开时，左右滑动、浏览器或系统返回键会优先收起浮层。
- 阅读页按职责分层：`ReaderPage` 负责状态与阅读命令，`ReaderWorkspace` 承载唯一一份正文渲染和桌面分栏，`ReaderMobileChrome` 管理移动端底栏与浮层；桌面端和移动端切换时不会创建第二套 EPUB 阅读器。
- PWA 可以缓存界面静态资源；书籍和学习数据仍需连接学习中心数据服务。
- 远程模式使用应用内登录页和安全会话 Cookie，并可在设置页修改登录账号与密码。
- 设置页“关于”中展示当前软件版本号与更新时间；版本号包含提交标识，发布构建时自动同步。

## 数据服务

服务首次启动时会创建独立的 `data/` 目录：

```text
data/
├── state.json                  # 书籍、RSS、视频字幕、进度、高亮、对话、设置和笔记元数据
├── auth.json                   # 登录凭据哈希与会话签名密钥
├── books/                      # EPUB 原文件
├── notes/<bookId>/<noteId>.md  # Markdown 笔记正文
└── search-indexes/             # 按需生成的书内搜索索引
```

默认目录是项目根目录下的 `data/`。可以通过 `LEARNING_CENTER_DATA_DIR` 改到其他磁盘、备份目录或容器挂载卷。

运行时数据不再依赖浏览器 localStorage 或 IndexedDB。备份、恢复或迁移时，直接复制完整的 `data/` 目录即可。

### 旧版浏览器数据自动迁移

当服务端还没有 `state.json` 时，网页会自动读取当前浏览器来源下旧版的 `learning-center-state-v1` 和 `learning-center-db`，依次迁移：

- EPUB 文件与已有书内索引
- 书架、阅读进度和阅读记录
- Markdown 笔记、高亮与评论
- AI 对话、模型配置和联网搜索配置

迁移完成后，应用只使用服务端数据。旧浏览器数据会保留为可恢复备份，不会自动删除。

浏览器安全策略不允许网页读取其他域名或端口的存储。如果旧版曾使用不同地址，请先让新版在原地址启动一次完成迁移。例如 `localhost:5173` 与 `127.0.0.1:5173` 被浏览器视为两个不同来源。

## 启动方式

环境要求：Node.js `^20.19.0` 或 `>=22.12.0`，以及 npm。

### 本机使用

安装依赖后，一个命令完成构建并启动：

```bash
npm install
npm start
```

默认访问地址：

```text
http://127.0.0.1:4174/
```

本地模式固定绑定 `127.0.0.1`，不会直接暴露到局域网或公网。

### 本地开发

```bash
npm run dev
```

该命令同时启动 Node 数据服务和 Vite，默认访问：

```text
http://127.0.0.1:5173/
```

其他常用命令：

```bash
npm test         # 运行服务端数据、API Key 与认证回归测试
npm run build    # 类型检查并生成生产构建与 PWA 文件
npm run verify   # 依次执行测试和生产构建
npm run preview  # 使用 Node 服务运行现有生产构建
```

### 远程访问

远程模式会监听所有网络接口。浏览器先进入简约的应用登录页，填写账号和密码；登录成功后通过安全会话 Cookie 访问数据 API：

```bash
LEARNING_CENTER_MODE=remote \
LEARNING_CENTER_USERNAME=admin \
LEARNING_CENTER_PASSWORD='请替换为足够长的密码' \
LEARNING_CENTER_DATA_DIR=/srv/learning-center-data \
LEARNING_CENTER_PORT=4174 \
npm start
```

可用环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LEARNING_CENTER_MODE` | `local` | `local` 仅本机访问，`remote` 开启远程访问和认证 |
| `LEARNING_CENTER_USERNAME` | `admin` | 数据目录首次初始化时使用的登录账号 |
| `LEARNING_CENTER_PASSWORD` | `password` | 数据目录首次初始化时使用的登录密码 |
| `LEARNING_CENTER_PORT` | `4174` | Node 服务端口 |
| `LEARNING_CENTER_DATA_DIR` | `./data` | 用户数据目录 |
| `LEARNING_CENTER_RSS_REFRESH_INTERVAL_MS` | `1800000` | RSS 服务端刷新周期，最小 60000 毫秒 |
| `LEARNING_CENTER_RSS_REFRESH_INITIAL_DELAY_MS` | `15000` | 服务启动后首次安排 RSS 刷新的延迟 |

内置服务提供 HTTP，不直接管理 TLS。对公网开放时必须放在 Nginx、Caddy 或其他 HTTPS 反向代理后面，不要用明文 HTTP 传输密码、书籍和 API Key。

首次登录时，环境变量中的账号密码会生成 `data/auth.json`；密码仅保存带随机盐的哈希，连续登录失败会触发短时限制。登录后可以在“设置 → 账户”中为当前账号设置新密码，修改结果保存在数据目录并优先于环境变量，容器重启后仍然有效。若数据目录已存在，单独修改 Docker 环境变量不会覆盖设置页保存的凭据。

### Docker 部署

仓库提供多阶段 `Dockerfile` 和 `compose.yaml`。镜像以非 root 用户运行，应用文件系统保持只读；唯一需要持久化的 `/data` 会绑定到宿主机指定目录。书籍、笔记、搜索索引、应用状态和 API Key 都在这个目录中，迁移或备份时复制整个目录即可。

先创建配置文件：

```bash
cp .env.example .env
```

`.env` 中最重要的配置如下：

```dotenv
LEARNING_CENTER_USERNAME=admin
LEARNING_CENTER_PASSWORD=请替换为足够长的随机密码
LEARNING_CENTER_DATA_DIR=/srv/learning-center-data
LEARNING_CENTER_BIND_ADDRESS=127.0.0.1
LEARNING_CENTER_PORT=4174
```

创建数据目录并启动：

```bash
mkdir -p /srv/learning-center-data
docker compose up -d --build
```

默认访问 `http://127.0.0.1:4174/`。未修改 `.env` 时，默认账号是 `admin`，默认密码是 `password`；请在首次登录后前往“设置 → 账户”立即修改。查看状态和停止服务：

```bash
docker compose ps
docker compose logs -f learning-center
docker compose down
```

Linux 上如果挂载目录不可写，把 `.env` 中的 `LEARNING_CENTER_UID` 和 `LEARNING_CENTER_GID` 设置为 `id -u`、`id -g` 的结果，并确保数据目录属于该用户。Docker Desktop 通常可以保留默认的 `1000:1000`。

默认端口只绑定到宿主机回环地址。需要通过其他机器或 HTTPS 反向代理访问时，将 `LEARNING_CENTER_BIND_ADDRESS` 改为适当的监听地址；公开到网络前仍必须配置 HTTPS。升级时重新执行 `docker compose up -d --build`，挂载的数据目录不会被镜像重建覆盖。

### 自动部署到 Docker 服务器

`.github/workflows/deploy.yml` 在 `main` 分支更新后构建并验证镜像，将带有 Git commit digest 的不可变镜像发布到 GHCR，再通过专用 SSH 账号调用服务器上的受限部署脚本。工作流会把提交标识和提交时间写入前端版本信息；服务器只在部署期间使用当前任务的短期 `GITHUB_TOKEN` 拉取镜像，不保存长期镜像仓库凭据。

生产服务器使用 `deploy/compose.production.yaml`，部署目录固定为 `/opt/learning-center`，持久化数据默认保存在 `/srv/learning-center-data`。`deploy/deploy.sh` 会等待容器健康检查；新镜像启动失败时自动恢复上一个 digest。`deploy/learning-center-deploy.sudoers` 只允许部署账号执行受控脚本。HTTPS 签发前使用 `deploy/nginx.bootstrap.conf`，它只开放 ACME 验证路径；证书就绪后再启用 `deploy/nginx.conf` 的 HTTPS 反向代理。生产环境的 `.env` 只保存在服务器，不提交到 Git。默认凭据 `admin` / `password` 仅用于首次启动，公网部署必须在 `.env` 中设置强密码或登录后立即修改。

GitHub 仓库需要创建 `production` Environment，并配置：

- Secrets：`DEPLOY_SSH_KEY`、`DEPLOY_KNOWN_HOSTS`
- Variables：`DEPLOY_HOST`、`DEPLOY_PORT`、`DEPLOY_USER`

工作流默认发布到 `https://learning-center.island-x.autos`。HTTPS 反向代理应把请求转发到服务器回环地址 `127.0.0.1:4174`，不要直接把容器端口暴露到公网。

## AI 模型配置

1. 打开左侧“设置”。
2. 在“AI 模型”中点击“添加模型”。
3. 填写名称、OpenAI 兼容 Base URL、API Key 和模型列表。
4. 进入书籍阅读页、RSS 内容详情或视频学习页，在 AI 输入框左下角选择供应商和模型。

Base URL 可以填写版本根路径，例如：

```text
https://api.openai.com/v1
```

应用会请求对应的 `/chat/completions`。如果地址已经包含该路径，会直接使用填写的地址。

模型与搜索 API Key 保存在服务器数据目录的 `state.json` 中，文件默认仅允许启动服务的系统用户读写。AI、联网搜索和网页读取请求都由学习中心服务端发出，前端只访问同源的 `/api/ai/jobs`，因此模型端点不需要额外支持浏览器 CORS。

服务端运行中的 AI 任务保存在内存里，最终对话会写入 `state.json`。关闭浏览器或短暂断网不会影响生成；如果 Node 进程、Docker 容器或服务器在生成过程中重启，尚未完成的任务会中断，需要重新发送问题。

### 导入与导出 API Key

设置页右上角提供“导入 API Key”和“导出 API Key”：

- 导出文件只包含已配置的模型与联网搜索 API Key，以及恢复模型配置所需的名称、API 地址和模型列表，不包含书籍、笔记、对话或阅读记录。
- 导入时按模型配置 ID 更新已有 Key，并添加导入文件中不存在于当前服务的模型配置；不会删除当前已有配置。
- 导入和导出接口与其他数据接口使用相同的访问认证。远程使用时仍应通过 HTTPS 反向代理访问。
- 导出的 JSON 文件包含明文凭据，请只保存在可信设备并妥善保管。

## 当前范围

- 本地书籍当前仅支持 EPUB，不支持 PDF、MOBI 等格式；网络订阅支持常见 RSS、Atom 与 RDF 格式。
- 视频学习当前只支持公开且可嵌入的 YouTube 视频；字幕与翻译是否可用取决于视频作者和 YouTube，当平台接口变化或所在网络无法访问 YouTube 时导入可能失败。
- 服务是单用户模式，不提供多用户账号、权限分组或实时协作。
- 多个浏览器可以读取同一数据目录，但不建议同时编辑同一条笔记；并发写入采用后写入者覆盖前写入者。
- 少数排版特殊或纯图片 EPUB 可能无法建立正文搜索索引。
- AI 能力取决于所配置端点的 OpenAI 兼容程度和模型能力。
