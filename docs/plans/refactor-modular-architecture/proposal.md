# 模块化架构重构提案

## 背景

学习中心已经包含书架、EPUB 阅读器、RSS、视频学习、AI、认证和本地持久化。功能持续增长后，部分页面、全局状态和服务端入口承担了过多职责，增加了理解成本、修改风险和回归验证难度。

## 目标

- 在界面、交互、路由、API、数据目录和持久化语义不变的前提下重构内部结构。
- 将前端整理为按领域组织的模块化单体，将服务端整理为路由、应用编排和基础设施边界清晰的模块化单体。
- 建立自动化类型检查、静态检查、单元测试、集成测试和关键行为回归门禁。
- 保留本地优先、单用户、Node 文件存储、Zustand persist、Foliate.js 和 PiAgent 等现有技术决策。

## 非目标

- 不进行 UI 改版、功能增删、框架升级、数据库替换、微服务拆分或多用户扩展。
- 不改变现有公开路径、HTTP 契约、SSE 行为、Cookie、ETag、状态字段或数据文件权限。
- 不部署或修改远程环境。

## 成功标准

- 原有自动化测试全部通过，新增领域纯函数与模块边界测试通过。
- `npm run verify` 和 `git diff --check` 通过。
- 旧数据快照可直接加载，状态版本变化时具备显式迁移。
- 桌面与移动、浅色与深色的关键流程行为保持一致。
- 大型入口文件被拆为可独立理解和测试的领域模块，跨领域依赖通过公开接口发生。
