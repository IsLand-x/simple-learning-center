# B站与 YouTube 内容源 PRD

## 1. 文档信息

- 产品：学习中心
- 功能：内置视频平台内容源
- 优先级：P0
- 目标版本：待排期
- 依赖：现有 RSS 时间线、服务端调度器、YouTube 视频学习模块

## 2. 产品目标

让用户无需部署 RSSHub，即可在学习中心持续接收以下公开内容更新：

1. B站当前一期“每周必看”；
2. 一个或多个指定 B站 UP 主的最新投稿；
3. 一个或多个指定 YouTube 频道的最新视频。

抓取到的内容应像普通 RSS 条目一样参与未读、收藏、搜索、日报、时间线和 AI 阅读流程。YouTube 视频可以进一步进入现有视频学习模块。

## 3. 成功标准

这是本地优先的单用户功能，不增加遥测。是否成功通过本地可观察结果判断：

- 用户可以在两分钟内完成任一内置来源的添加并看到首批内容；
- 服务端关闭浏览器后仍会定时刷新来源；
- 同一视频不会因重复刷新产生重复条目；
- 更新或删除 B站 Cookie 不需要重建订阅源；
- 单个来源失败不会影响其他来源刷新；
- 原有 RSS、Atom、RDF、OPML、日报和 YouTube 单视频导入行为不回退。

## 4. 用户场景

### 4.1 添加 B站每周必看

用户打开 RSS 页，点击“添加订阅源”，选择“B站每周必看”。该来源不需要输入地址，用户可以选择文件夹和显示名称。确认后立即读取当前一期内容。

系统只允许存在一个“B站每周必看”来源，重复添加时定位到已有来源。

### 4.2 订阅 B站 UP 主

用户选择“B站 UP 主”，粘贴 UP 主空间地址或输入纯 UID。系统解析 UID，预览 UP 主名称和最近投稿；用户确认后添加。

匿名请求可用时直接完成。若 B站返回风控或登录校验错误：

- 已配置 Cookie：使用 Cookie 重试；
- 未配置 Cookie：保留当前表单并提示前往“设置 > 内容源”配置；
- Cookie 疑似失效：提示替换 Cookie，并展示最近一次验证时间。

### 4.3 订阅 YouTube 频道

用户选择“YouTube 频道”，可以粘贴以下任一形式：

- `https://www.youtube.com/@handle`；
- `https://www.youtube.com/channel/UC...`；
- `@handle`；
- `UC...` 频道 ID。

系统解析并保存稳定的频道 ID，预览频道名称和最近视频，然后完成添加。重复输入同一频道的不同 URL 形式时，应识别为同一来源。

### 4.4 从 Feed 进入 YouTube 视频学习

YouTube Feed 条目提供“加入视频学习”操作：

- 视频尚未加入时，按现有流程读取详情和字幕，保存后打开视频学习页；
- 视频已经存在时，直接打开对应视频；
- Feed 刷新本身不批量抓字幕，避免无用数据和上游请求。

该能力为 P1，不阻塞三类 Feed 的 P0 上线。

## 5. 功能需求

### FR-1 内容源类型

添加订阅源弹窗包含以下类型：

- RSS / Atom 地址；
- B站每周必看；
- B站 UP 主；
- YouTube 频道。

选择内置来源后，内容类型固定为“视频”，不再要求用户手动选择“文章 / 视频 / 社交媒体”。普通 RSS 保留现有类型选择。

### FR-2 来源解析与预览

提交前由服务端校验输入、规范化来源标识并获取首批内容。预览至少返回：

- 来源名称；
- 来源主页；
- 来源描述或当前期次；
- 最近内容数量；
- 规范化后的来源描述。

解析失败时不创建空来源。

### FR-3 去重

- B站视频优先使用 `bvid`，缺失时使用 `aid`；
- YouTube 视频使用 11 位视频 ID；
- 来源使用规范化后的 UP 主 UID 或 YouTube 频道 ID 去重；
- 现有条目的已读、收藏、全文、摘要和翻译状态在刷新后必须保留。

### FR-4 自动刷新

继续使用现有服务端错峰串行调度。默认最小刷新间隔：

| 来源 | 最小间隔 |
|---|---:|
| 普通 RSS / Atom / RDF | 沿用全局刷新周期 |
| YouTube 频道 | 30 分钟 |
| B站 UP 主 | 60 分钟 |
| B站每周必看 | 6 小时 |

实际间隔取“全局刷新周期”和“来源最小间隔”的较大值。手动刷新绕过最小间隔，但同一来源已有请求运行时不得重复启动。

### FR-5 条目展示

三类来源复用现有 RSS 视频条目样式，至少展示：

- 标题；
- 作者或 UP 主 / 频道名；
- 发布时间；
- 封面；
- 简介；
- 原始视频链接。

B站每周必看来源额外在来源描述中展示当前期数和期名。若上游没有可靠发布时间，条目以首次抓取时间为回退值，不伪造发布日期。

### FR-6 B站 Cookie 管理

设置页新增“内容源”标签和“B站凭证”区域，支持：

- 粘贴并替换 Cookie；
- 保存后立即验证；
- 查看“未配置 / 未验证 / 有效 / 疑似失效”状态；
- 查看最近验证时间与脱敏账号信息；
- 删除 Cookie。

前端永远不能读取已保存 Cookie 原文。再次编辑时输入框为空，保存即替换。删除使用项目统一确认弹窗。

### FR-7 错误与恢复

来源行和管理界面继续展示最近错误，并为下列错误提供可操作文案：

- B站 Cookie 未配置；
- B站 Cookie 疑似过期；
- B站风控校验失败；
- B站 UP 主不存在；
- YouTube 频道无法识别或不存在；
- YouTube 网络或代理不可用；
- 上游超时或限流。

成功刷新后自动清除旧错误。定时刷新失败不弹全局 Toast；用户手动刷新时才即时提示。

### FR-8 管理与删除

内置来源继续支持：

- 修改显示名称；
- 移动文件夹；
- 手动刷新；
- 标记已读；
- 删除来源及其条目、标注和日报关联。

“自动原文”对内置视频来源禁用，因为其简介已由适配器提供，视频页也不适合通用文章正文提取。

### FR-9 OPML

- 普通 RSS 行为不变；
- YouTube 频道导出官方 Atom 地址，并附带学习中心来源扩展字段；
- B站来源导出 `learningCenterSourceKind` 和规范化标识，不包含 Cookie；
- 学习中心重新导入时能无损恢复三类来源；
- 导出包含其他阅读器无法识别的 B站来源时，向用户提示兼容性限制。

## 6. 数据与隐私要求

- B站 Cookie 仅能发送到预先写死的 B站 HTTPS 域名和只读 GET 接口；不能附加到任意用户输入 URL。
- Cookie 不进入 `state.json`、前端 Zustand、日志、错误正文、测试快照或 OPML。
- Cookie 文件使用原子写入和仅当前系统用户可读写的权限。
- 远程模式下沿用现有登录认证，并在 UI 中继续提示使用 HTTPS。
- 不保存 B站或 YouTube 视频文件；只保存 Feed 元数据以及用户主动导入的 YouTube 字幕和学习数据。

## 7. 交互约束

- 不新增一级导航，继续使用现有“RSS”和“视频”。
- 新文案使用简体中文，平台名和技术标识除外。
- 添加弹窗在移动端保持 16px 输入字号和至少 44px 主要触控目标。
- 所有异步提交提供 loading、disabled 和错误状态，防止重复提交。
- 内置来源图标继续使用 Semi Icons，不增加平台品牌色或第三方图标库。

## 8. 验收标准

### B站每周必看

- 能无 Cookie 添加并显示当前一期；
- 重复添加不会创建第二份来源；
- 连续刷新不产生重复条目；
- 当前期切换后保留旧期已抓取条目。

### B站 UP 主

- 空间 URL 和纯 UID 均可添加；
- 相同 UID 的不同输入形式能够去重；
- 正常返回时展示最近投稿的标题、作者、封面、简介和链接；
- 风控和 Cookie 失效时展示明确恢复入口；
- 替换 Cookie 后无需重建来源即可恢复刷新。

### YouTube 频道

- `@handle`、频道 URL 和频道 ID 均可解析；
- Feed 条目按视频 ID 稳定去重；
- 复用现有 YouTube 代理配置与错误提示；
- P1 完成后，可以从条目进入已有视频学习页且不会重复导入。

### 回归

- 普通 RSS / Atom / RDF 添加、手动刷新和后台刷新正常；
- 浏览器旧快照不会覆盖服务端已刷新条目或新来源描述；
- 删除来源继续清理相关条目和标注；
- 桌面浅色、桌面深色、移动浅色、移动深色下均可完成添加和凭证管理。

## 9. 后续方向

- B站字幕和视频学习；
- 多 B站账号与按来源选择凭证；
- 可选 RSSHub sidecar 或浏览器自动化兜底；
- 小红书等高维护内容源；
- 用户可配置的单来源刷新频率。
